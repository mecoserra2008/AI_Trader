## 1. What changed, in plain words

**Collector (crates/at-flow).** A 3 s candle no longer closes on the first later book message. It closes when both the
trade stream and the book stream of that symbol have passed its end; for a quiet symbol, when the wall clock is 1.5 s
past the end and the streams that have not passed it have been silent for 1.5 s; and at the latest 30 s after its end
while a stream lags. Trades executed inside a candle are therefore booked into it even when the trade topic lags the
book topic, which is the defect WS02 measured (per-3 s trade counts matched the archive 57% of the time, the lake was
always late). A trade that lags past the 30 s cap goes into the oldest open candle (totals stay exact) and is counted.
Each websocket connection is now supervised: no data for 30 s means a stall or a dead session after standby, so it is
torn down and reconnected (a quiet market after a reconnect doubles the threshold, up to 8 min). Every 60 s each
connection logs a `heartbeat` line (messages, trades, book updates, trade lag mean / max, late trades, symbols without
trades, reconnects) and warns `trade feed trickling` when trades fall below 20% of their trailing rate while the book
keeps flowing: the `trade_deficit` pattern becomes visible live. Config: settings.yaml `flow.max_hold_ms`,
`flow.silence_secs`, `flow.heartbeat_secs` (defaults in code: 30000 / 30 / 60). The schema is unchanged.

**Why the feeds stopped on 2026-11-07..10.** They never ran live. `atx update` only ever had bars (last/mark 1h/4h/1d),
funding, open interest at one interval (4h), DVOL and Fear & Greed. The other feeds were one-off backfills:
`scripts/backfill_research.sh` on 11-07 (instruments, index 1h, ls_ratio 4h, stablecoins), manual runs 11-07..10 (OI 1h
and ls_ratio 1h for BTC, index 1h for 18 symbols, flow_bars for 51 symbols), and a static import of the user's earlier
project for Deribit funding and deribit_svi (ending 2026-10-09/10). The launcher scripts proposed Task Scheduler
entries for the daily jobs, which the standing user constraint rules out, so `flow maintain` never ran either.

**Updater (crates/atx/src/updater.rs, crates/at-alt).** New streams, configured in settings.yaml `live:`:
the daily linear instrument snapshot (00:05 UTC), DefiLlama stablecoins (daily), Deribit perp funding (hourly; a new
at-alt fetcher, same convention as the import: event = hour start, known = hour end + 2 s), and `live.extra`: OI 1h
(BTC), ls_ratio 4h (the 23 research symbols) and 1h (BTC), index 1h bars (the 18 symbols of the backfill). A stream
without a cursor now resumes from the newest row already in the lake for that stream, so the first start after the
deploy closes each hole since 11-07 without a single duplicate row (before: it started at now - 3 days, which is where
the ~35k duplicate rows came from, and would have left 11-07..11-24 empty).

**deribit_svi known_ts: verified, no fix needed.** The fits use only trades strictly before 08:00 UTC: the fetch keeps
`timestamp < T` (BACKTEST_TREND_FOLLOWING research/btc_options/fetch_data.py::fetch_day) and the fit filters again
(harness/surface.py::fit_day, `trades.timestamp < T_ms`). known_ts = 08:01 is valid. The feed now runs daily
(src/ai_trader/storage/deribit_svi.py: the same fetch and the project's own svi_v2 harness). Reproduction check on
2026-10-09: stored value = refit from the old raw file = refit from a fresh fetch, all 12 series identical to 5 decimals.

**flow_3s maintenance** (src/ai_trader/storage/flow.py) is runnable: cold days only (before today UTC and no file
written in the last 2 h), DuckDB with a 1.5 GB limit for compaction, rollup one symbol at a time, reversible (old files
to data/lake_backup/<run>/, manifest). It runs daily with flow_bars (the last 2 days of the trade archive) and the 08:00
Deribit surface as the `daily_ops` loop of scripts/ops/desk_start.sh (src/ai_trader/storage/daily.py, 08:20 UTC,
through the governor). `desk_start.sh` also takes names now (`bash scripts/ops/desk_start.sh daily_ops` starts one
process) and says at the top that it must be run after every reboot; no OS auto-start was added.

**Lake cleanup** (src/ai_trader/storage/repair.py): every step writes the cleaned partition next to the old files,
verifies the new file against the intended rows as multisets (both EXCEPT ALL directions empty, no duplicates left),
swaps, moves the old files to data/lake_backup/<run>/ and appends a manifest line (rows in / distinct / dropped / added
/ out, sha256, the dropped and changed rows). `python -m ai_trader.storage.repair undo --run R` restores a run,
`purge --run R` deletes its backup once you are satisfied (the manifest is kept in data/lake_backup/manifests/).

## 4. Caveats

- Candles written before the deploy keep the old trade timing (late by up to tens of seconds in bursts). For sub-minute
  trade timing on those days use the WS02 archive fills or minute aggregates.
- The new rule makes `known_ts` later when a stream lags (up to 30 s after the candle end) and 1.5-2 s after the end for
  quiet symbols (before: the first book message, usually < 0.2 s). This is the honest time the candle was complete.
- The 30 s silence reconnect bounds a stale book to ~30 s (quiet candles carry the last book state until the reset).
- The flow_bars hole 2026-11-11..11-25 is not filled: it is a data decision (about 10-13 GB of archive downloads; BTC
  alone is 155 MB a day; transient, the stored rows are small). Command in section 6.
- The instrument snapshot lists what Bybit returns by default (trading instruments): a delisted symbol shows up as
  missing from later snapshots, not with status Closed.
- deribit_svi depends on the earlier project's harness at C:/Users/Asus/Documents/BACKTEST_TREND_FOLLOWING (read only,
  env BTF_ROOT to move it). If that folder goes, the daily svi step fails loudly and the other jobs still run.

## 6. Deploy steps (orchestrator; Git Bash, repo root)

The desk loops (desk_start.sh) restart `bin/atx-updater.exe` / `bin/atx-collector.exe` 10 s after they exit. A running
exe cannot be overwritten on Windows but it can be renamed, so: rename, copy, then kill the old process.

B. Build once, after every agent's Rust change is in. A2 is still changing crates/at-risk and crates/atx/src/live.rs
   (and its at-risk/src/live.rs:1512 currently fails clippy), so this single release build waits for A2:
   `.venv/Scripts/python.exe scripts/ops/governor.py run --mb 3000 --slots heavy --name deploy-build -- cargo build --release
   -p atx -j 1` (→ target/release/atx.exe; -j 1 because -j 4 hit the 3000 MB cap). The same exe serves the updater, the
   collector, bin/atx-ops.exe and (A2's concern) bin/atx-live.exe.

U. Updater first (its downtime is the window for the hot-partition repairs):
   1. `PID=$(powershell -NoProfile -Command "(Get-CimInstance Win32_Process -Filter \"Name='atx-updater.exe'\").ProcessId")`
   2. `mv bin/atx-updater.exe bin/atx-updater.old.exe && taskkill //F //PID $PID` (the loop now fails every 10 s with
      "No such file": harmless; the cursor file is saved after every write, nothing is lost).
   3. Hot repairs, 2-4 min: `.venv/Scripts/python.exe scripts/ops/governor.py run --mb 1800 --slots light --name d8-hot --
      .venv/Scripts/python.exe -m ai_trader.storage.repair d8-fixes --only oi --allow-hot`, then the same with
      `-m ai_trader.storage.repair dedup --allow-hot --table bars --table funding --table open_interest --table alt_series`.
   4. `cp target/release/atx.exe bin/atx-updater.exe` (the loop starts it within 10 s), then `rm bin/atx-updater.old.exe`.
   5. Check: `tail -40 logs/updater_$(date -u +%Y%m%d).log`: "N streams without a cursor resume from the newest lake row",
      one "resuming from the lake" line per new stream, then heartbeats with errors 0. The first cycles backfill ls_ratio /
      OI 1h / index 1h since 2026-11-07, Deribit funding since 10-10, stablecoins since 11-06, and take an instrument snapshot.

C. Collector:
   1. `mv bin/atx-collector.exe bin/atx-collector.old.exe && cp target/release/atx.exe bin/atx-collector.exe`
   2. `PID=$(powershell -NoProfile -Command "(Get-CimInstance Win32_Process -Filter \"Name='atx-collector.exe'\").ProcessId")`
   3. Kill right after a flush (a hard kill loses what is buffered since the last 5-min flush):
      `L=logs/collector_$(date -u +%Y%m%d).log; n=$(grep -c flushed $L); until [ $(grep -c flushed $L) -gt $n ]; do sleep 2; done; taskkill //F //PID $PID`
   4. After ~70 s: `grep -E "websocket subscribed|heartbeat|stream silent" logs/collector_$(date -u +%Y%m%d).log | tail -15`
      (9 subscribed lines, then one heartbeat per connection per minute). Then `rm bin/atx-collector.old.exe`.

D. Daily jobs: `cp target/release/atx.exe bin/atx-ops.exe`; run once now: `.venv/Scripts/python.exe scripts/ops/governor.py
   run --mb 2500 --slots heavy --name daily_ops -- .venv/Scripts/python.exe -m ai_trader.storage.daily >> logs/daily_ops.log 2>&1`
   (the latest 08:00 surface, flow_bars for the missing recent days, ~1.5 GB transient download; flow_3s days are already
   compacted up to 11-27); then start the loop alone:
   `bash scripts/ops/desk_start.sh daily_ops` (next run 08:20 UTC).
   Optional, a data decision: close the flow_bars hole 11-11..11-24 (~10 GB transient download, 1-2 h):
   `... -m ai_trader.storage.daily --only flow_bars --flow-bars-since 2026-11-11`.

P. In a few days, once nothing looks wrong: `.venv/Scripts/python.exe -m ai_trader.storage.repair purge --run <run>` for each
   folder in data/lake_backup/ (undo instead: `... repair undo --run <run>`).

After any reboot: `bash scripts/ops/desk_start.sh` (no OS auto-start exists, by the user's constraint).
